# Domain docs

Quorum SQL uses a single-context layout with `GLOSSARY.md` at the repo root and architecture decision records (ADRs) under `docs/adr/`.

Before exploring, read the glossary and any ADRs relevant to the work. Proceed with the available context when either is absent.

Use the glossary's terms in specs, tickets, proposals, and tests. Check existing code and docs for established usage when a term is missing. Use `domain-modeling` to resolve real gaps and record terms or decisions as they become clear.

When a proposal conflicts with an ADR, cite the ADR and explain why the decision merits revisiting. Create `GLOSSARY.md` when the first domain term is resolved and `docs/adr/` when there is a decision to record.
